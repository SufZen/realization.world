1. Strategic Goal

The system is not designed to “make AI videos.” Its purpose is to create a durable, searchable, high-quality public representation of Realization’s expertise and Asaf’s thinking with minimal recurring production effort.

1

Capture real expertise

Continuously harvest knowledge from active projects, meetings, decisions, documents and research.

2

Convert it into media

Turn private operational knowledge into safe, useful, well-structured public content.

3

Build authority

Use long-form and short-form media to make the brand’s expertise legible to people, search engines and AI systems.

Core principle: Automate the production of expertise. Do not automate the creation of expertise.

Primary business outcomes

  • Build Realization as an authority in real estate development, architecture, urban regeneration, AI-enabled operations and systems thinking.
  • Increase discovery among investors, project partners, clients, developers, founders and AEC/PropTech operators.
  • Demonstrate Asaf’s cross-disciplinary X-factor: architecture + development + investment + systems thinking + AI + execution.
  • Create a growing public knowledge asset that supports trust, referrals, partnerships, hiring, consulting and deal flow.
  • Reduce founder filming time by using a high-quality trained digital avatar for most recurring content.

2. Operating Principles

Real work first

Topics originate from actual work, recurring questions, decisions, lessons, research and operating experience.

Avatar-first, human-anchored

The avatar handles scalable delivery. Real appearances are reserved for trust, story, emotional weight, site work and important messages.

One engine, many outputs

One knowledge object creates channel-native derivatives. Do not run separate ideation engines per platform.

Modular production

Generate scenes, not entire videos. This improves quality, lowers retry cost and enables reuse.

Privacy by architecture

Meetings are internal research sources. Public outputs contain generalized knowledge, not identifiable confidential cases.

No tool sprawl

Use the existing stack first. Add paid services only when a measured bottleneck materially affects quality or automation.

4. Channel Architecture: Realization vs Founder

Purpose: institutional authority, expertise, case studies, frameworks, projects, AI × real estate, development knowledge.

  • YouTube: primary long-form authority asset.
  • Instagram: Reels, architecture, project visuals, selected educational clips.
  • TikTok: experimental short-form discovery.

Founder / Asaf Layer

Purpose: worldview, interpretation, lessons, founder/operator perspective and professional credibility.

  • LinkedIn: primary founder authority and B2B distribution.
  • X: short observations, opinions, experiments and links.
  • Facebook: secondary distribution where an existing audience justifies it.

6. Privacy, Confidentiality & Public-Safe Transformation

RAW PRIVATE SITUATION → PRIVATE INSIGHT → GENERALIZED EXAMPLE → PRINCIPLE / FRAMEWORK → PUBLIC CONTENT

Risk levels

LevelMeaningRule
P0 PublicAlready public, sourceable informationUsable with normal fact-checking
P1 GeneralizablePrivate origin but safe after anonymizationMay proceed automatically after privacy transform
P2 SensitiveCould reveal project, party, price, negotiation, legal or identifying contextHeavy abstraction + human approval
P3 ConfidentialActive negotiations, identifiable counterparties, legal matters, investors, proprietary client dataNever publish automatically

Red-list categories

  • Active negotiations or bids
  • Investor identities and fundraising discussions
  • Legal, tax, litigation or regulatory disputes
  • Pending planning applications where disclosure creates risk
  • Exact confidential prices, bids, budgets or financing terms
  • Personal data and identifiable client stories
  • Counterparty strategies or internal weaknesses
  • Non-public project addresses where disclosure is not approved

Composite case rule

When a lesson is valuable but the original case is identifiable, combine multiple similar cases and change nonessential details while preserving the principle.

8. Digital Character / Avatar Build

8.1 Objective

Build a persistent digital representation of Asaf that remains convincing across angle, lighting, wardrobe and environment. The standard is identity consistency under variation, not a single good talking-head shot.

8.2 Training inputs

  • Target: 30–50 curated recent photos
  • Straight-on, 3/4 left/right, profiles, close-up, medium and full body
  • Neutral, smiling, thoughtful and speaking expressions
  • Indoor + outdoor
  • Professional + casual clothing
  • Good lighting and unobstructed face
  • Prefer consistency in current appearance

8.3 Existing video use

  1. Frame extraction: extract sharp, varied identity frames for Soul ID training.
  2. Behaviour calibration: learn gestures, cadence, expressions and presentation energy.
  3. Real B-roll: reuse genuine site visits, talks, interviews and project footage.

  • Voice identity

9. Voice Strategy

Start entirely inside Higgsfield. Test custom voice / user voice element, Seed Audio and native Seedance speech. Compare pronunciation, cadence, warmth, authority, accent fidelity and long-form fatigue. Add ElevenLabs only if the pilot proves voice quality is the limiting factor.

Avoid written prose

“The feasibility assessment of a real estate development requires the analysis of several interdependent factors.”

Prefer spoken language

“Here’s something developers learn very quickly. A building can work perfectly on paper—and still be a terrible development.”

10. Content Production System

10.1 Long-form

Initial target: 5–15 minutes. The avatar is the host, not the whole video. Recommended mix: 30–40% host footage and 60–70% supporting visuals.

  • Plans and architectural drawings
  • Maps
  • Financial models and simplified charts
  • Timelines
  • Construction details
  • Site footage
  • Public case studies
  • Documents / screenshots
  • 3D models / conceptual visuals
  • Typography and diagrams

10.2 Short-form

Target: 30–75 seconds. One insight, one promise, one payoff. Avatar can occupy more of the runtime. Prefer counterintuitive observations over generic tip lists.

13. Automation Cadence & Human Approval

13.1 Weekly ingestion

Every week:
  1. Fetch recent Fireflies meetings.
  2. Fetch relevant recently modified Drive files.
  3. Retrieve new internal notes / approved voice notes.
  4. Extract insight objects.
  5. Deduplicate against the content ledger.
  6. Run privacy classification.
  7. Cluster against the knowledge graph.
  8. Score candidates.
  9. Produce weekly editorial brief.

16. AI Agent Implementation Specification

Agent A — Source Harvester

Inputs: Fireflies, Drive, internal notes. Outputs: normalized source records with IDs, timestamps, source type, privacy default and raw text.

Agent B — Insight Extractor

Outputs: atomic knowledge objects. Extract problems, decisions, frameworks, mistakes, questions and lessons. Separate speaker claims from verified facts.

Agent C — Privacy Transformer

Outputs: privacy level + generalized public-safe version. Remove names, addresses, exact project identity, emails, investor identity and sensitive commercial terms. Escalate P2. Block P3.

Agent D — Knowledge Graph / Deduplication Agent

Cluster related insights, flag duplicates and calculate recurrence / expertise strength.

Agent E — Editorial Ranker

Apply the scoring model and reject high-genericness / low-expertise candidates.

Agent F — Research / Verification Agent

Verify factual claims using primary or authoritative sources. Never convert a private-meeting claim into a public fact without verification.

Agent G — Script Agent

Produce hook options, final spoken script, CTA and production cues. Do not fabricate personal experience.

Agent H — Storyboard / Visual Director

Create scene list with clear visual ownership: avatar / diagram / B-roll / playback / text.

Agent I — Higgsfield Production Agent

Generate presenter clips, supporting visuals, assembled master and cover. Use short presenter segments, preserve Soul ID and voice consistency, record job IDs and exact parameters, and perform QA.

Agent J — Channel Adaptation Agent

Create separate Realization brand versions and Asaf founder versions. Do not duplicate identical captions everywhere.

Agent K — Publisher

Use Buffer for founder channels and Metricool for Realization channels. Respect AI disclosure, account identity and scheduling. Record post IDs.

Agent L — Analytics Agent

Feed post performance and lead quality back into editorial weights. Optimize for authority and business relevance, not raw reach alone.

17. Content State Machine

CANDIDATE → SHORTLISTED → APPROVED → RESEARCHED → SCRIPTING → STORYBOARDED → PRODUCTION → QA → READY → SCHEDULED → PUBLISHED → ANALYZED → EVERGREEN / ITERATE / ARCHIVE

Hard stops

  • BLOCKED_PRIVACY — P3 or unresolved disclosure risk
  • BLOCKED_EVIDENCE — factual claim cannot be verified
  • BLOCKED_IDENTITY — avatar or voice inconsistent
  • BLOCKED_ACCOUNT — publishing target ambiguous or wrong brand identity

16. Optimize for authority, relevance and business outcomes—not vanity reach.
